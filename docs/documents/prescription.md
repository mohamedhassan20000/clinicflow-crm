# Prescription Requirements

**Definition id:** `prescription`
**Prefix:** `RX`
**Paper:** ISO A5, portrait
**Formats:** authenticated preview, print, PDF download
**Numbering:** clinical traceability sequence

This specification inherits [shared requirements](SHARED_REQUIREMENTS.md).

## 1. Purpose and non-purpose

A prescription is a doctor-authored medication order for one authorized patient. It communicates exactly what the doctor attested, in a format intended for the patient and dispensing professional.

It is not:

- a diagnosis or treatment recommendation generated by ClinicFlow or AI;
- a medication-administration record;
- proof that medicine was dispensed;
- a controlled-drug prescription unless a separately approved compliance profile supports it; or
- a substitute for the prescriber’s professional judgment.

## 2. Generation point, actor, trigger, and preconditions

- Generation point: authorized patient/encounter clinical surface.
- Actor: authenticated doctor only, with current RLS access to the patient.
- Trigger: explicit doctor “Review and issue” confirmation after medication entries pass validation.
- Optional appointment link: the current authorized encounter may be attached, but a prescription is not generated automatically from appointment completion or a medical note.

Preconditions:

- authorized active patient;
- server-resolved doctor identity and clinic;
- professional licence number and any required specialty/registration;
- at least one complete medication line;
- explicit doctor attestation;
- output language reviewed by the doctor; and
- approved jurisdiction/prescription legal profile.

If ClinicFlow cannot classify controlled/restricted medicines reliably, the baseline issuer must block medicines flagged as controlled by an approved drug catalog and warn that unclassified free text cannot be represented as a compliant controlled prescription.

## 3. Current source-of-truth assessment

Patient, doctor, department, appointment, and free-text medical notes exist. Structured medications, drug identifiers, allergies, diagnoses, clinician professional licences/specialties, refills, dispense status, and prescription instances do not.

P7E therefore needs explicit doctor-authored structured input and durable prescription persistence. It must not parse a medical note into medication lines or infer an allergy/diagnosis.

## 4. Complete field catalog

### Prescription and patient

| Field | Requirement | Source / rule |
|---|---|---|
| `prescription_number` | Required | `RX-YYYY-000001`, unique per clinic. |
| `prescribed_at` | Required | Issue timestamp, clinic timezone. |
| `valid_until` | Conditional | Required when legal/profile or medicine rules impose validity. |
| `patient_full_name` | Required | Patient snapshot. |
| `patient_file_number` | Required | Patient snapshot. |
| `patient_date_of_birth` | Required | Patient snapshot. |
| `patient_national_id` | Conditional | Legal-profile requirement only. |
| `patient_sex` | Conditional | No current source; render only if explicitly added and legally/clinically needed. |
| `patient_weight` | Conditional | Explicit encounter value with unit/time; never inferred. |
| `allergies_summary` | Optional but safety-significant | Explicit doctor-confirmed input. “No known allergies” may render only when affirmatively recorded, never from absence. |
| `encounter_date` | Optional | Authorized appointment snapshot. |
| `diagnosis_or_indication` | Optional, sensitive | Explicit doctor input; never inferred from service/department/note. |

### Medication table

| Field | Requirement | Rule |
|---|---|---|
| `medication_name` | Required | Generic name preferred; doctor-authored or selected from approved catalog. |
| `brand_name` | Optional | Separate from generic name. |
| `drug_code` | Optional | Approved catalog identifier only. |
| `strength` | Required | Value plus unit, e.g. `500 mg`. |
| `dosage_form` | Required | Tablet, capsule, solution, etc. |
| `route` | Required | Oral, topical, etc. |
| `dose` | Required | Per-administration amount. |
| `frequency` | Required | Structured schedule plus localized display. |
| `duration` | Required | Value/unit or explicit ongoing instruction where legally allowed. |
| `quantity_to_dispense` | Required | Value plus unit. |
| `start_date` | Optional | Clinic-local date. |
| `administration_instructions` | Optional | Doctor-authored; no implicit translation. |
| `as_needed` | Optional | Boolean plus required indication/max frequency when true. |
| `refills` | Conditional | Explicit non-negative count only when legally supported. |
| `substitution_allowed` | Conditional | Explicit doctor choice when legal profile supports it. |
| `controlled_class` | Internal/conditional | Approved drug-catalog classification; not model-generated. |

At least one line is required. Every line is independently complete; ditto marks and “same as above” are forbidden.

### Prescriber

| Field | Requirement | Rule |
|---|---|---|
| `prescriber_full_name` | Required | Authenticated doctor snapshot. |
| `prescriber_professional_licence` | Required unless approved profile says otherwise | P7E source gap; blocks issue when absent. |
| `prescriber_specialty` | Conditional | Explicit professional specialty, not assumed from department. |
| `prescriber_department` | Optional | Department snapshot. |
| `clinic_licence` | Conditional | P7C clinic licence metadata. |
| `prescriber_contact` | Conditional | Approved professional/clinic contact only. |

## 5. Section and table order

1. clinic/prescriber branding and prescription number/date;
2. patient identity and safety context;
3. optional diagnosis/indication;
4. medication table/list;
5. general instructions/notices;
6. prescriber attestation, wet-sign/stamp line;
7. optional ClinicFlow verification QR; and
8. legal footer.

Medication lines may continue to a second A5 page; prescriber identity and prescription number repeat.

## 6. Numbering and lifecycle

- `RX-<clinic-local YYYY>-<six digits>`.
- Issue requires doctor confirmation and an immutable snapshot.
- Corrections create a replacement prescription and mark the original replaced/void; they never overwrite medication directions.
- Reprint visibly preserves issue date and status.
- Dispense/cancel/refill consumption state is not implemented by this definition.

## 7. Signature and QR

- Doctor typed attestation and wet-sign/stamp line are required by baseline.
- No patient signature.
- Electronic/cryptographic signing remains out of scope.
- Optional QR verifies document status and issuer only. It must not expose medications, diagnosis, or patient identity.

## 8. Localization, branding, and degradation

- System labels render ar/en; the doctor reviews medication content in the selected language.
- Drug names/codes, units, and Latin abbreviations remain direction-isolated. Ambiguous abbreviations are discouraged.
- Missing optional brand, code, indication, instructions, refills, substitution, logo, and contact fields collapse.
- Missing doctor licence, medicine line data, or approved legal profile blocks issue.
- Absence of allergy data renders “Allergy status not recorded” only if the approved design/legal profile permits; it must never render “none.”

## 9. Delivery

Preview, print, and PDF download only. P7 adds no prescription send to Email or WhatsApp and no pharmacy integration. Clinical contents must not enter existing message bodies.

## 10. Legal gates

Kuwait enablement requires field-by-field review of the Ministry of Health prescription-information, prescribing-practice, and dispensing decrees listed in [legal validation](LEGAL_VALIDATION.md). Controlled/restricted medicine support requires a separate approved scope.

## 11. Fixtures and acceptance

- one and many medications; long Arabic/English directions;
- PRN medicine with mandatory limits;
- allergy explicitly recorded versus unknown;
- missing licence and incomplete line denial;
- doctor-only and cross-patient/cross-clinic denial;
- replacement preserves original;
- QR contains no clinical data;
- A5 multi-page continuity; and
- ar/en print/PDF parity.

## 12. Explicitly out of scope

- prescribing suggestions, drug interaction/dose checking, AI content;
- drug catalog procurement unless separately scoped;
- controlled-drug workflow;
- pharmacy e-prescribing/dispensing;
- refill consumption and medication-administration records;
- digital signature; and
- P7B visual design or P7C–P7E implementation.
