## Final Verdict: **APPROVED WITH MINOR FINDINGS**

P4.5B is a careful, well-scoped, defense-in-depth implementation. Every headline requirement is met and independently verified against the code and the local-DB behavior encoded in the integration suite:

- **Credential confidentiality** — keys are validated once, sealed in a versioned AES-256-GCM envelope with AAD bound to `clinic + provider + credentialId`, and stored in service-role-only tables. The plaintext exists only in a request-scoped return value; no action, metadata query, audit row, or client payload can surface it.
- **Strict BYOK isolation is real, not advisory** — the strict path constructs *only* the direct Anthropic adapter (no managed model object is ever built), and the reconciler hard-rejects any non-zero managed cost for a strict reservation (`42501`). Both layers were verified.
- **Hybrid fallback is audit-before-spend and non-oscillating** — a pre-stream direct failure triggers `onFallback` → `log_ai_provider_fallback` (which re-validates the persisted disclosure + the exact active hybrid reservation) *before* any managed call; a failed audit throws and no managed request is issued; fallback is sticky for later model steps.
- **Managed-credit reconciliation is idempotent and correct** — the wrapper captures adjust-eligibility before delegating, the inner P4.5A reconcile is status-guarded, and the whole call is one transaction, so a lost-response retry cannot double-subtract.
- **Authorization is layered** — primary-admin + AI-entitlement gate in the server action, re-checked independently inside every lifecycle RPC via `assert_primary_ai_provider_admin`; nav and page guards mirror it.

No **Critical** or **High** findings. Five **Low** findings and two **Info** items are catalogued below; none block progression to P4.5C. See §12 for the required-vs-deferred split.

## 2. Credential Encryption & AAD Binding — **Strong**

`lib/ai/platform/credential-crypto.ts`:

- AES-256-GCM, fresh 12-byte random IV per encryption, 16-byte auth tag, 32-byte key enforced (`KEY_INVALID` on any other length). Envelope = `[format:1][keyVersion:2][iv:12][tag:16][ciphertext]`; decrypt reads the key version from the envelope so old versions decrypt during rotation while new writes use `AI_CREDENTIALS_ACTIVE_KEY_VERSION`.
- **AAD** binds the ClinicFlow context string + `format:1` + `clinic:<id>` + `provider:<p>` + `credential:<connectionId>` (NUL-joined). A ciphertext relocated to a different clinic, provider, or connection id fails `DECRYPT_FAILED` — a genuine cryptographic tenant-isolation guarantee, not just a WHERE clause. Encrypt (`credentialId = new connectionId`) and both decrypt sites (`credentialId = row.id`) use consistent context.
- Envelope length/format is validated before use; corrupt/short/odd-hex input fails closed (`ENVELOPE_INVALID`). Tampering is caught by GCM tag verification.
- Fingerprint is a truncated SHA-256 (`sha256:xxxxxxxx…xxxx`), one-way and non-reversible; the DB `CHECK` regex and the TS generator use the identical U+2026 ellipsis (verified byte-for-byte).
- Uses a **dedicated** key ring (`AI_CREDENTIALS_KEY_V*`), explicitly separate from `MESSAGING_CREDENTIALS_KEY` (runbook rule enforced by construction).

The crypto unit test covers randomized output, round-trip, missing/invalid key, cross-version decrypt, tamper, and clinic/credential AAD mismatch. No weaknesses found.

## 3. Authorization & Reauthentication — **Strong**

- `requirePrimaryAiAdmin()` = `requireMutationRole("admin")` → `isPrimaryClinicAdmin` → `hasFeature(ai_assistant)`. A manager fails at role; a secondary admin fails at primary; an unentitled clinic fails at feature. All three collapse to a generic error (no oracle). The DB independently re-enforces primary-admin inside every lifecycle RPC (verified: `nonPrimary`/`crossClinic` calls raise `AI_PROVIDER_PRIMARY_ADMIN_REQUIRED`).
- **Reauthentication** uses a throwaway anon client `signInWithPassword` and confirms `data.user.id === user.id`, then signs the throwaway session out. Required for rotation (when a connection already exists), every mode change, and revoke — i.e., exactly the state-changing paths. First-connection create is intentionally reauth-free (the admin is already authenticated); acceptable.
- **Rate limiting** is per-operation (`credential-write`/`credential-test`/`mode-write`/`credential-revoke`), keyed `clinic:user`, 5 / 15 min, `failureMode: "closed"`, and is consumed **before** password verification so wrong-password attempts still burn the budget. This bounds the reauth brute-force surface to primary admins only.
- Page (`redirect("/dashboard")`) and nav (`canManageAi`) guards mirror the action gate; the settings surface is fail-closed for managers, secondary admins, and unentitled clinics.

## 4. Strict BYOK Isolation — **Strong**

Two independent enforcement layers, both verified:

1. **Adapter layer** (`tenant-provider.ts`): `mode === "byok_strict"` returns `{ model: directModel, transport: "anthropic_direct" }` and never calls `managedGatewayProvider.prepare`. The routing test asserts a strict provider failure propagates and `prepareManaged` is never invoked.
2. **Accounting layer** (migration reconcile wrapper): `credential_mode = 'byok_strict' AND p_managed_cost_micros <> 0` → raise `42501`. `execution.ts` computes `managedCostMicros = 0` for strict, and the DB trigger derives `byok_provider_direct`. The integration test reconciles a strict success and asserts `spent_micros == 0` and `billing_disposition == 'byok_provider_direct'`.

Because the wrapper subtracts `actual - managed` from `spent_micros` and managed is forced to 0, strict spend is removed from ClinicFlow's included-credit pool **regardless of magnitude** — this path is immune to the P4.5A-M1 over-run edge.

## 5. Hybrid Fallback & Audit-Before-Spend — **Strong**

- `hybridFallbackMiddleware` wraps both `wrapGenerate` and `wrapStream`. On a pre-stream error it classifies the failure; `request_failed` (unclassified/4xx client errors) **re-throws without fallback**; any infra/auth/quota/timeout class calls `await onFallback(errorClass)` and only then sets `managedActivated = true` and issues the managed call. If `onFallback` throws, `managedActivated` stays false and the error propagates — **no managed request, no managed spend**. All four behaviors are covered by the routing test (audit once → stay managed; audit failure → zero managed calls; unclassified → no fallback).
- The audit RPC `log_ai_provider_fallback` re-validates at spend time: it requires an active `reserved` hybrid reservation for `(request_id, clinic, actor)` **joined to** a live `hybrid` policy with `hybrid_disclosure_version = 'p45b-hybrid-disclosure-v1'` and a non-null acceptance. If the admin revoked/changed the policy mid-request, the audit fails and the request fails closed — matching the report's "revalidated before managed execution" claim. Verified: missing reservation → `AI_PROVIDER_HYBRID_POLICY_REQUIRED`.
- Fallback is **sticky and non-oscillating**: `managedActivated` persists in the middleware closure across model steps, so later steps go straight to managed.
- Billing consistency: pre-fallback direct attempts carry `fallback_parent_attempt_id = null` → DB derives `byok_provider_direct` and `execution.ts` excludes them from `managedCostMicros`; the failed fallback marker is `nonbillable_failed`; post-fallback attempts carry a non-null parent → `managed_included` and are counted as managed. The two independent computations (SQL trigger per-row vs. app aggregate) use identical logic, so they stay consistent.

## 6. Managed-Credit Reconciliation Idempotency — **Correct**

The 7-arg `reconcile_ai_budget` wrapper:

- Validates `0 <= managed <= actual` and the per-mode invariants (managed==actual for `managed`; managed==0 for `byok_strict`).
- Captures `v_should_adjust := status = 'reserved'` **before** delegating to the P4.5A inner reconcile (which adds `actual` to `spent_micros` and flips status to `reconciled`/`released`, and itself returns `false` when status is not `reserved`).
- Applies the direct-cost subtraction only when `v_reconciled AND v_should_adjust AND direct > 0`, guarded by `spent_micros >= direct`.

**Idempotency proof:** on a retry, the inner reconcile returns `false` *and* `v_should_adjust` was captured as `false` (status already advanced) — double-guarded, so the subtraction never repeats. Because the wrapper is a single `SECURITY DEFINER` invocation (one transaction), a failure in the wrapper's own period update rolls back the inner reconcile too, so a retry re-runs cleanly from `reserved`. The integration test issues `reconcile` twice and asserts `{ reserved_micros: 0, spent_micros: 0 }` for the strict case. Net managed accounting (`spent += actual - direct = managed`) is correct for managed/strict/hybrid.

## 7. Secret Leakage, Logging & Sentry Scrubbing — **Strong**

- No `console.*`/logger calls in the credential paths (grep-verified). The action returns only `{ success, error, health, operation }`; the action unit test asserts the raw secret never appears in the serialized result.
- `getAiProviderSettings` → `metadata()` strips `credential_encrypted`; the client component receives only provider/health/fingerprint/timestamps.
- `scrub.ts` (loaded at Sentry instrumentation time) filters credential-bearing object keys **and** value shapes including `sk-ant-*`, generic `sk-*`, `Bearer …`, and `\x…` bytea envelopes (≥40 hex), with cycle/depth guards. The integration test asserts the fallback audit `new_data` contains no `credential_encrypted`.
- Audit rows across create/rotate/test/mode/revoke/fallback carry only provider, fingerprint, lifecycle/policy state, and error class — no ciphertext, no key material.

## 8. Tenant Isolation, Rotation & Revocation Safety — **Strong**

- Both new tables have RLS enabled, **no** authenticated policy, and `all` revoked from `public/anon/authenticated` (tenant `select` denied — verified). They are also added to `CLINIC_SCOPED_TABLES`, so every server-side read through `createClinicScopedAdminClient` gets an injected `clinic_id` filter; RPC/schema/storage remain blocked on that wrapper.
- **Rotation** (`activate_ai_provider_connection`) locks the clinic row `FOR UPDATE` (serializes even first-create where no active row exists), retires the previous row with `credential_encrypted = NULL`, inserts the new active row, and writes metadata-only audit — atomically. The `one_active_idx` partial unique index guarantees at most one active connection per `(clinic, provider)`. Validate-before-persist: `activateAnthropicCredential` tests the key and only encrypts/activates on `valid`, so a bad key leaves the previous connection intact (verified by the "atomic rotation" integration test).
- **Revocation** destroys ciphertext, sets `revoked`, and resets the policy to `managed` in one transaction — verified to null the ciphertext and return routing to managed. The `secret_lifecycle` CHECK enforces `credential_encrypted IS NULL` for retired/revoked rows, so the runbook's "retired/revoked rows have null ciphertext" invariant is structurally guaranteed.
- Key-rotation story is coherent: envelope carries its version; old `AI_CREDENTIALS_KEY_V*` stay decrypt-only; a missing old key fails closed as `credential_unavailable` and (for strict) never falls back to managed.

## 11. Findings Summary

| ID | Severity | Area | Summary |
|---|---|---|---|
| **L1** | Low | Auth consistency | `lib/primary-admin.ts::getPrimaryClinicAdminId` orders by `created_at asc` only and omits `is_deleted = false`, whereas the DB `assert_primary_ai_provider_admin` uses `is_deleted = false` **and** the deterministic tiebreak `order by created_at asc, id asc`. On exact `created_at` ties (bulk/seeded admins) or an inconsistent `is_deleted`/`deleted_at` state, app and DB can name different "primary" admins. Fail-closed (DB is authoritative → generic action failure or page redirect), not exploitable, but a latent correctness/UX gap. Align the app query to the DB predicate + tiebreak. |
| **L2** | Low | Accounting trust surface | For `hybrid`, the reconcile wrapper only range-checks `0 <= managed <= actual`; the managed/direct dollar split that adjusts `spent_micros` is application-supplied and not re-derived in SQL from the inserted attempts (unlike `managed`=actual and `byok_strict`=0, which are enforced). Per-row `billing_disposition` *is* DB-derived. Server-only + service-role gated ⇒ low risk, but the report's "without trusting application-supplied values" holds fully only for managed/strict. Consider computing the managed sum in SQL. |
| **L3** | Low | Defense-in-depth | The 20-arg `reserve_ai_budget` and 7-arg `reconcile_ai_budget` wrappers run validation (and, for reconcile, a `SELECT … FOR UPDATE`) before delegating to the auth-gated inner function; they lack their own leading `auth.role() = 'service_role'` check that the other P4.5B RPCs have. EXECUTE is revoked from anon/authenticated and granted only to `service_role`, and the inner call re-checks, so tenants cannot reach it (same shape approved in P4.5A). Add a top-of-body role check for symmetry. |
| **L4** | Low / Product | Budget model | Strict/hybrid reservations still claim and retain one `ai_messages` legacy unit, so a BYOK clinic paying its own provider remains capped by ClinicFlow's message-count quota even though its token spend is removed from the managed pool. Intentional ("preserves the established `ai_messages` entitlement") and arguably a P4.5C plan decision — flag so the decoupling is deliberate. |
| **L5** | Low | Test coverage | No end-to-end reconciliation test for a hybrid request with an actual fallback (`managed_cost > 0`) asserting `spent_micros == managed_cost` and mixed pre-/post-fallback dispositions. Add one integration scenario to lock the `execution.ts`→wrapper seam. |
| **INFO-1** | Info | Hygiene | `getAiProviderSettings` selects `credential_encrypted` then discards it in `metadata()`. Never reaches the client; consider omitting the column from the read-path SELECT to minimize in-memory secret handling. |
| **INFO-2** | Info | Migrations | The reserve/reconcile overloads rely on SQL argument-count resolution to shadow the P4.5A signatures. Verified non-recursive (wrappers call the shorter inner arities) and both grants are service-role only. Brittle-by-nature (a future defaulted param could shift resolution); noted for awareness. |

Carried context: **P4.5A-M1** (per-step input guard excludes system/tool tokens) remains open but is out of P4.5B scope; note that the strict BYOK path is structurally immune to it (net-zero managed adjustment), and the hybrid managed portion inherits P4.5A's existing behavior.

No **Critical** or **High** findings.

## 12. Recommendation

**Approved.** P4.5B is safe to proceed to **P4.5C**.

- **Must-fix before P4.5C:** none are blocking. **L1** (primary-admin app/DB divergence) is the one worth resolving early because P4.5C touches entitlement/plan wiring where a "who is primary" mismatch could compound — a one-line query alignment. **L2** becomes more load-bearing once `spent_micros` is a billable meter in P4.5C, so schedule the SQL-side managed-cost derivation alongside that work.
- **May be deferred:** **L3** (RPC role-check symmetry), **L4** (BYOK vs. `ai_messages` quota — resolve as an explicit P4.5C product decision), **L5** (hybrid mixed-cost integration test), and **INFO-1/2**.

The credential boundary is cryptographically tenant-isolated, strict BYOK is doubly enforced, hybrid fallback is consented + audited-before-spend + non-oscillating, managed-credit reconciliation is idempotent, and no secret-leakage, RLS, or Phase-4/4.5A-regression defect was found.
