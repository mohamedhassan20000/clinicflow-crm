## Observations (non-blocking; no action required)

These are design confirmations, not findings — recorded so the P4.10B reviewer has continuity.

- **`user_choice` `set_by` is currently unreachable.** It is defined in `ACTIVE_CONTEXT_SET_BY` for the P4.10B clarification-pick UI and has no writer in P4.10A. This is intentional forward-compatibility, documented in both the module and the report, and cannot be reached from model input.
- **The advisory prompt places a real patient UUID in model context.** This is consistent with the already-reviewed `page-context.ts` mechanism, the prompt explicitly instructs the model never to display an internal id, and the id grants no access (re-authorized every call). Acceptable and consistent.
- **`persistDoctorTurn` writes context/messages/title as separate statements** (not one transaction). This is the pre-existing persistence shape, unchanged by P4.10A; the `active_context` write is idempotent and gated on `contextChanged`, so no new correctness risk is introduced.
- **P4.10B carry-forward guarantee:** when P4.10B renders `display_label` in a React chip, it must continue to keep the label out of model context (prompt and tool arguments), preserving property #6. The report already flags this.
