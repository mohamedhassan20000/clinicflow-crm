## Final Verdict

**APPROVED WITH MINOR FINDINGS.** Phase 4.5 meets the roadmap's acceptance criteria and is ready for final fixes and merge once the two required items below (both small; one is documentation) are closed. No Critical or High findings. The phase-level acceptance holds as implemented:

- A `pro_ai` clinic on managed mode uses AI through the certified Gateway route without a provider account; strict BYOK runs on the direct adapter with cryptographically tenant-bound credentials and can rotate/revoke; hybrid requires persisted, versioned disclosure and an audit-before-spend RPC.
- A `basic` or `pro` clinic cannot invoke a model by any route: the app pins every AI feature to `planSlug === 'pro_ai'` ([lib/entitlements.ts:136](../../lib/entitlements.ts#L136)), and the database independently pins it in `effective_ai_feature` / `resolve_ai_commercial_limits` (migration `…140000`), so even an operator feature override cannot turn Basic/Professional into an AI plan — exactly the 2026-07-19 commercial decision. Verified by tests on both layers.
- Every attempt reconciles to a content-free ledger event; concurrency and the cost pool are enforced in one serialized SQL transaction; strict-BYOK spend is structurally excluded from the managed pool; the hybrid managed split is re-derived in SQL and fail-closed on mismatch.
- No credential, PHI, prompt, or patient identifier crosses the client/log/Sentry/Gateway-tag boundary in any path reviewed.

## 2. What Was Independently Verified

### 2.1 Clean-state migration correctness

The six-migration chain was read end-to-end for fresh-database ordering:

1. `…120000` creates tables (with the M1 clamp trigger and the named `actual <= reserved` CHECK already folded in), the 19-arg reserve and 6-arg reconcile.
2. `…121000`/`…122000` are guarded no-ops on a fresh database (local-dev reconciliation only).
3. `…123000` renames the 19-arg body to `reserve_ai_budget_p45a_limit_v1` and re-creates the public 19-arg wrapper with the DB-authoritative pool ceiling.
4. `…130000` widens `credential_mode`/`billing_disposition` constraints (drop-by-generated-name matches Postgres auto-naming), adds credential/policy tables, lifecycle RPCs, the disposition trigger, and the 20-arg/7-arg wrappers.
5. `…140000` replaces the inner reserve with the commercial-limit body (keeping `#variable_conflict use_column`), replaces the 19-arg wrapper (now resolving `resolve_ai_commercial_limits`), replaces the 20-arg wrapper (provider-mode + policy + connection-health enforcement + billing-bucket stamping), replaces the disposition trigger and 7-arg reconcile (recognizing `managed_addon`/`managed_overage`), adds the policy-entitlement trigger, terms table, and operator report.

No ordering hazard found; the implementer's successful `supabase db reset --local` is consistent with this reading. The remaining string-surgery/no-op migrations are a hygiene item only (P45-I2 — nothing is committed yet, so folding is still possible).

### 2.2 Tenant isolation & RLS

- All five new AI tables: RLS enabled, no authenticated policies (except `ai_commercial_terms`, which uses the same `is_platform_admin()` all-command policy pattern as `clinic_feature_overrides`), explicit revokes, service-role grants. `ai_usage_events` is insert-only even for service role (immutability trigger allows only cascade delete at `pg_trigger_depth() > 1` for whole-tenant erasure).
- All five tables are registered in `CLINIC_SCOPED_TABLES` ([lib/supabase/admin.ts:1239](../../lib/supabase/admin.ts#L1239)), so every scoped server read gets an injected clinic filter.
- Credential ciphertext is additionally bound by AES-GCM AAD to `clinic + provider + credentialId`; a relocated envelope fails to decrypt. Cross-clinic/non-primary denial is enforced in-DB by `assert_primary_ai_provider_admin` and covered by integration tests.
- `subscriptions.clinic_id` is `unique`, so the `operator_ai_usage_report` subscription join cannot fan out rows.

### 2.3 Concurrency, budget, and reconciliation

- All reserve-path checks (stale-lease reclaim, duplicate-request idempotency, concurrency count, pool check, `increment_usage`, reservation insert, `reserved_micros` bump) execute under the per-clinic-period `FOR UPDATE` lock inside one `SECURITY DEFINER` transaction. The new `AI_BUDGET_CONCURRENCY_EXCEEDED` check (`ai_concurrent_requests`, plan-seeded 4) is inside the same lock.
- The inner reserve now re-resolves `resolve_ai_commercial_limits` and rejects a stale caller ceiling (`AI_BUDGET_STALE_COMMERCIAL_LIMIT`); the app-side `budgetLimitMicros` is genuinely just a hint.
- Reconciliation: attempts key-allowlisted and typed; sum(final_cost) must equal `p_actual_cost_micros`; the 7-arg wrapper enforces managed==actual (managed), managed==0 (strict), and re-derives the hybrid managed sum in SQL across all three managed buckets, failing closed on mismatch; the direct-cost subtraction is double-guarded (`v_reconciled AND v_should_adjust`) so retries cannot double-subtract. The app-side hybrid split in [execution.ts:329-344](../../lib/ai/platform/execution.ts#L329-L344) mirrors the DB trigger exactly (only successful post-fallback attempts are managed).
- Provider over-run (A-M1): `spent_micros` books the full observed cost, the reservation column is clamped by trigger, and subsequent requests are denied by the pool — spend is never dropped or refunded. Verified in migration + report + integration test list.
- Legacy `ai_messages` remains an atomic request/fair-use unit in every credential mode (documented product decision, B-L4), compensated on failed/aborted/expired outcomes.

### 2.4 Provider routing & credential lifecycle

- Managed: Gateway adapter pins `only: [anthropic]`, requests ZDR, sends content-free tags, and no identity unless the optional HMAC pseudonym key is set.
- Strict BYOK: only the direct Anthropic adapter is ever constructed; the reconciler independently rejects non-zero managed cost (`42501`).
- Hybrid: middleware classifies pre-stream failures, refuses fallback on `request_failed`, audits via `log_ai_provider_fallback` (which re-validates the live policy row, disclosure version `p45b-hybrid-disclosure-v1`, and the exact active reservation) before any managed call, and is sticky/non-oscillating.
- Lifecycle: validate-before-encrypt, atomic rotation with old-ciphertext destruction, revocation resets policy to managed in one transaction, reauth via throwaway password client on rotate/mode/revoke, per-operation fail-closed rate limits, metadata-only audit rows, Sentry scrubber extended with `sk-ant-*`/`sk-*`/bytea shapes.
- New P4.5C reserve-time enforcement: the 20-arg RPC verifies the mode is entitled (`ai.managed` / `ai.byok` / `ai.hybrid_fallback`), matches the persisted clinic policy, and that a healthy active connection exists for non-managed modes — the DB now refuses a BYOK reservation even if application state drifted. The policy-write trigger (`enforce_ai_provider_mode_entitlement`) blocks unentitled `byok_strict`/`hybrid` writes while always allowing the fail-safe reset to `managed`.

### 2.5 Billing attribution & operator surfaces

- Billing buckets: reserve-time stamping of `managed_billing_disposition` (included → addon → overage by pool position), trigger-derived per-event disposition, strict/hybrid direct spend excluded from `spent_micros` in the same transaction. Totals reconcile; see P45-M2 for the bucket-precision caveat.
- `operator_ai_usage_report`: platform-admin-gated in-body, month-aligned validation, aggregates only (no actor ids, tokens fine, no content), reconciles period `spent_micros` against the summed immutable ledger. Operator clinic page adds `ai_commercial_terms` management (pro_ai-only, USD→micros with safe-integer guard, audited via `logOperatorAction`, entitlement cache invalidated). Operator provider-health report projects mode/health/timestamps only — no fingerprints, key versions, or ciphertext.
- Clinic surface: `/settings/ai` is primary-admin + entitlement gated at layout, page, action, and DB layers; `AiUsageSummary` reads only aggregates via `getClinicAiCommercialUsage` (no events, no actors).

### 2.6 Phase-4 behavior preservation

The chat route diff preserves the P4B gate order (auth → rate limit → validation → reserve → history → model), the virtual-first-turn and failed-turn non-persistence behavior, temperature 0.2 / 1500 output tokens / 8 steps (now policy-owned), and the degrade paths (429 on budget/concurrency denial, generic fail-closed on lookup errors). `staffTaskForRole` maps doctor → `staff_clinical_summary`, others → `staff_administrative`, matching the shipped role model.

## 4. New Findings

No Critical or High findings.

### Medium

**P45-M1 — Missing P4.5C implementation report (documentation/process; blocks merge per repo contract).**
`docs/reports/` contains `P4_5A_IMPLEMENTATION.md` and `P4_5B_IMPLEMENTATION.md`, but no `P4_5C_IMPLEMENTATION.md`, and P4.5C never received a dedicated sub-phase review before this phase review (this document now serves as its review). Every prior sub-phase shipped an implementation report as part of the Claude↔Codex handoff contract, and P4.5C contains the phase's most commercially sensitive changes (catalog mutation, commercial terms, DB-authoritative limits, operator reports).
**Why it matters:** the report is the durable record of what P4.5C claims to do, its verification runs, and its intentional limitations; the merge/PR narrative and future audits depend on it.
**Fix:** write `docs/reports/P4_5C_IMPLEMENTATION.md` in the established format (outcome, architecture, files, verification commands with results, intentional limitations) before the implementation commit.
**Blocks merge:** yes (documentation only — no code change).

**P45-M2 — Billing bucket (`included`/`addon`/`overage`) is stamped at reservation time from worst-case commitments, not derived at reconciliation from actual spend.**
`…140000` (20-arg reserve, lines 655–677) computes `managed_billing_disposition` from `spent + reserved` *including this reservation's worst-case amount* at reserve time; the disposition trigger then copies that bucket onto every successful managed attempt, immutably. Because actual cost is typically far below the worst-case reservation, and concurrent reservations reconcile in arbitrary order, an attempt can be permanently recorded as `managed_addon`/`managed_overage` when the clinic's actual cumulative spend never left the included allowance — and (less often) the reverse.
**Why it matters:** period totals (`spent_micros`) remain exactly correct, and today billing is manual, so nothing is mischarged now. But the roadmap positions this ledger as "deterministic billing evidence"; the moment add-on/overage invoicing is computed *from event dispositions*, the misbucketing becomes a real over/under-charge.
**Fix (either):** (a) re-derive the bucket at reconcile time inside the 7-arg wrapper from the period's post-reconciliation cumulative managed spend and stamp it on the just-inserted attempts before they become visible (they are inserted in the same transaction; the immutability trigger would need a narrow allowance or the derivation must move into the insert path); or — much cheaper — (b) record in the P4.5C report and the operator-report description that event-level buckets are *reservation-time estimates* and that invoicing must be computed from period aggregates (`included_limit`/`addon_limit`/`overage_limit` vs `spent_micros`), which are exact.
**Blocks merge:** no, provided option (b)'s documentation lands with P45-M1.

### Low

**P45-L1 — Settings panel offers Hybrid (and Strict BYOK) without knowing the clinic's mode entitlements.**
`pro_ai` seeds `ai.byok: true` but `ai.hybrid_fallback: false`, so hybrid requires an operator override by design. The panel ([components/settings/ai-provider-settings.tsx](../../components/settings/ai-provider-settings.tsx)) disables strict/hybrid only when no healthy connection exists; an un-entitled primary admin discovers the denial only after typing their password, as a generic "mode not included" error (`setAiProviderMode` → `hasAiProviderMode`; DB trigger enforces independently). Fail-closed and correct, but poor UX for the phase's flagship Enterprise control. **Fix:** pass the resolved mode entitlements from the server page into the panel and disable/annotate unavailable modes.

**P45-L2 — 20-arg reserve runs entitlement/policy/connection checks before the idempotent duplicate-request return.**
A transport retry of an already-acquired request that straddles a policy/entitlement/connection-health change raises (`AI_PROVIDER_POLICY_MISMATCH` / `AI_PROVIDER_CONNECTION_NOT_HEALTHY`) instead of returning the existing reservation's status as the inner function would. Rare and fail-closed; the client then surfaces a generic error for a turn that may still be streaming. **Fix:** short-circuit the duplicate lookup before mode enforcement, or accept and note the behavior.

**P45-L3 — Superseded RPC arities remain service-role-executable.**
The 19-arg `reserve_ai_budget` (no provider-mode/policy/connection enforcement, leaves `credential_mode='managed'`) and the 6-arg `reconcile_ai_budget` (no managed-split correction — a direct call for a BYOK reservation would charge the managed pool) both retain `GRANT EXECUTE … TO service_role`. Current server code only calls the 20-/7-arg forms; this is defense-in-depth against a future caller mistake. **Fix:** revoke service_role EXECUTE on both inner arities (definer-owner calls from the wrappers are unaffected), matching the treatment of `reserve_ai_budget_p45a_limit_v1`.

**P45-L4 — Concurrency count is clinic-wide but stale-lease reclamation is period-scoped.**
The reclaim loop expires only current-period leases, while `v_active_reservations` counts `status='reserved' AND expires_at > now()` across all periods. Around a month rollover, crashed prior-month reservations can consume the concurrency budget (limit 4) for up to the 600 s lease with no path that expires them until a request arrives in *that* period. Self-healing and bounded. **Fix (optional):** drop the `period_start` predicate from the reclaim `UPDATE`, or scope the concurrency count to unexpired leases only (it already is) and accept the ≤10-minute window.

**P45-L5 — `ai_commercial_terms.updated_by` references `auth.users` with `ON DELETE RESTRICT`.**
Deleting a platform admin's auth account becomes impossible once they have saved terms for any clinic. Sibling operator artifacts use `set null`-style patterns. **Fix:** `on delete restrict` → keep only if intentional for audit; otherwise switch to `set null` with a nullable column or store the actor in the platform audit log only (it already is).

**P45-L6 — Clinic usage projection can display "exhausted" before enforcement blocks.**
`getClinicAiCommercialUsage` rounds (`Math.round`) and caps (`Math.min(100, …)`) the percentage: 99.5 % renders as the exhausted state while requests still succeed, and a genuine over-run (>100 % after an A-M1-style overrun) is hidden by the cap. Cosmetic; thresholds (70/90/100) otherwise match the proposal. **Fix:** floor instead of round for the threshold input, or compare raw micros for the `exhausted` state.
