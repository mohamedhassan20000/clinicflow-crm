## 3. Findings — required fixes

### P15C-R1 — HIGH — Early-access dialog submit from `/` is blocked by the authenticated-mutation/billing middleware gates

- **Affected:** [components/marketing/marketing-page.tsx:65](../../components/marketing/marketing-page.tsx#L65) (form now hosted on `/`), [lib/supabase/middleware.ts:39-51](../../lib/supabase/middleware.ts#L39-L51) (`PUBLIC_FLOW_PREFIXES` — `/` absent), [lib/supabase/middleware.ts:211-243](../../lib/supabase/middleware.ts#L211-L243) (authenticated-mutation + fail-closed billing gate)
- **Explanation:** Server Actions POST to the page that renders them. The form used to live on `/early-access`, a `PUBLIC_FLOW_PREFIXES` route whose documented invariant is: _"GET and Server Action POST requests must reach these routes untouched for anonymous AND authenticated visitors alike — a stale or half-provisioned session on a signup POST must never be bounced to /login mid-action."_ P1.5C moved the form to `/` without extending that exemption. For any request with a session cookie, `POST /` is now an "authenticated mutation": a stale/profileless session is 307'd to `/login` (middleware.ts:217-221), an expired-subscription clinic user is 307'd to `/dashboard?billing=subscription_required` (middleware.ts:238-243), and the server action never executes — the dialog silently does nothing.
- **Independently reproduced** with a scratch unit test against `updateSession` (see §6, command 6): anonymous `POST /` passes; profileless-session `POST /` → `/login`; canceled-subscription `POST /` → `/dashboard`. This is the exact class of production regression the existing test `tests/unit/lib/public-flow-middleware.test.ts` ("lets a stale/profileless session POST the signup form instead of bouncing it to /login") was written to prevent for `/signup`.
- **Required fix:** exempt `/` as a public flow using an **exact-path match** (never a prefix — `/` prefixes everything). E.g. treat `pathname === "/"` alongside `isPublicFlowPath()` in the early bypass at middleware.ts:113, or add a documented exact-match set. The action performs its own validation and rate limiting, exactly like the other public flows. Add a regression test mirroring the existing stale-session public-flow tests for `POST /`.
- **Verification:** unit test for `POST /` with (a) no user, (b) profileless user, (c) expired-subscription user — all must pass through; e2e submit of the dialog while logged in as an expired-trial user.
- **Blocks merge:** **YES**

### P15C-R2 — HIGH — Stale e2e: `tests/e2e/login.spec.ts` "root redirects to /login" fails against the new `/`

- **Affected:** [tests/e2e/login.spec.ts:3-7](../../tests/e2e/login.spec.ts#L3-L7)
- **Explanation:** the test asserts the pre-P1.5C contract (`/` → `/login`). The P1.5C spec inverts it ("anonymous `/` renders the marketing site (no login redirect)"). Confirmed failing: `Expected substring: "/login" / Received string: "http://localhost:3100/"` (§6, command 5).
- **Required fix:** replace with a test asserting anonymous `/` returns 200 and renders the marketing page (h1, `#early-access` section, primary CTA → `/login`) — this is itself the spec's first acceptance criterion, currently uncovered at e2e level.
- **Blocks merge:** **YES**

### P15C-R3 — HIGH — Stale e2e: the P1C signup flow (`tests/e2e/p1c-signup.spec.ts`) is red — form is now behind the dialog

- **Affected:** [tests/e2e/p1c-signup.spec.ts:38-44](../../tests/e2e/p1c-signup.spec.ts#L38-L44)
- **Explanation:** the flow test goes to `/early-access` (now a 308 to `/#early-access`) and fills `getByLabel("Clinic name")` directly; the form only exists inside the closed `Dialog`, so the locator times out and the entire request→invite→signup→onboarding→dashboard flow test fails (confirmed, §6 command 5). The spec's acceptance explicitly requires "all P1C signup/invitation e2e flows green" and "existing … tests keep passing against the moved form".
- **Required fix:** update the e2e to land on `/`, open the dialog (click "Request an invitation"), then fill/submit; keep the rest of the flow unchanged. While here, assert the `/early-access` → `/#early-access` redirect end-to-end (upgrades the weak source-grep test, see P15C-P8).
- **Blocks merge:** **YES**

### P15C-R4 — MEDIUM — Marketing copy is not translation-ready: most strings are hardcoded outside the copy module

- **Affected:** [components/marketing/marketing-page.tsx:12-23](../../components/marketing/marketing-page.tsx#L12-L23) (features, FAQs), [45](../../components/marketing/marketing-page.tsx#L45) (hero badges), [50-51](../../components/marketing/marketing-page.tsx#L50-L51) (hero mock labels), [56](../../components/marketing/marketing-page.tsx#L56), [58](../../components/marketing/marketing-page.tsx#L58), [60](../../components/marketing/marketing-page.tsx#L60), [62](../../components/marketing/marketing-page.tsx#L62), [64-65](../../components/marketing/marketing-page.tsx#L64-L65) (early-access section, dialog title/description, "spots taken" string), [68](../../components/marketing/marketing-page.tsx#L68), [70](../../components/marketing/marketing-page.tsx#L70) (footer); [lib/marketing-copy.ts](../../lib/marketing-copy.ts)
- **Explanation:** the spec is explicit: "Copy ships English-first with **all strings behind translation keys**; Arabic marketing copy lands with P2C." `lib/marketing-copy.ts` holds only nav/hero/early-access (~20% of visible copy); everything else is inline JSX literals, so P2C cannot translate the page without editing the component. The P1.5 phase gate also requires all P1.5 code be "translation-key-ready".
- **Required fix:** move every user-visible string (including the "N of M spots taken this week" template, which needs interpolation for translation) into `lib/marketing-copy.ts` (or equivalent keyed structure). No `next-intl` wiring — that stays P2.
- **Blocks merge:** YES (spec-explicit deliverable; cheap now, expensive after P2C starts)

### P15C-R5 — MEDIUM — Mobile has no functional navigation; the menu icon is a decorative no-op

- **Affected:** [components/marketing/marketing-page.tsx:32-35](../../components/marketing/marketing-page.tsx#L32-L35)
- **Explanation:** the nav links are `hidden … md:flex`; below `md` the header renders `<Menu className="size-5 md:hidden" aria-hidden />` — a bare SVG, not a button. It looks interactive but does nothing, is unreachable by keyboard, and mobile visitors (the majority for a marketing site; the Lighthouse budget is defined on mobile) have no way to reach Product/Features/Pricing/FAQ/Contact except manual scrolling. This fails the spec's premium-UX and accessibility bar.
- **Required fix:** either implement a real mobile menu (e.g. shadcn `Sheet`/`DropdownMenu` with `aria-expanded`, focus management) or remove the misleading icon and keep an always-visible minimal nav. Whichever is chosen, it must be keyboard-operable.
- **Blocks merge:** YES

### P15C-R6 — MEDIUM — Acceptance gaps: no Lighthouse gate (CI or documented manual) and no reduced-motion render test

- **Affected:** acceptance checklist (revised plan §8 P1.5C); [app/globals.css:263-275](../../app/globals.css#L263-L275); test tree (no new file covers either)
- **Explanation:** the spec requires "Lighthouse budget met in CI (**or documented manual gate**)" — neither exists: no CI job, no `docs/` note recording a manual run/scores — and "reduced-motion snapshot renders without animation" — the CSS block exists and looks correct, but nothing exercises it.
- **Required fix (minimum):** run Lighthouse (mobile) against a production build of `/`, record the scores and the ≥90 perf/accessibility gate as a documented manual procedure (docs/ or this file's re-review section); add a unit/e2e check for the reduced-motion path (e.g. emulate `prefers-reduced-motion` in Playwright and assert `.marketing-float` computes `animation: none`, or at minimum a CSS-contract unit test).
- **Blocks merge:** YES (acceptance-explicit; the budget claim is currently unverified by anyone)

## 4. Findings — optional polish (not blocking)

### P15C-P1 — `permanentRedirect` issues 308, spec says 301

[app/(public)/early-access/page.tsx:4](<../../app/(public)/early-access/page.tsx#L4>). Both are permanent redirects and browsers/search engines treat them equivalently for GET; 308 additionally preserves method. Fine to keep — note it in the implementation report, or use a middleware/next.config 301 if literal compliance is wanted.

### P15C-P2 — SEO metadata is minimal

[app/page.tsx:5-10](../../app/page.tsx#L5-L10) sets title/description/robots only. Missing: `metadataBase`/canonical (`https://www.clinicflow.fit` — production canonical; vercel.app previews should not be indexed), OpenGraph/Twitter cards, and there are no `sitemap.xml`/`robots.txt` routes even though the middleware matcher already carves them out. Recommend `alternates.canonical`, OG image, and a minimal `app/robots.ts` + `app/sitemap.ts`.

### P15C-P3 — Dark-theme session renders mixed light/dark UI on `/`

The root layout applies the `dark` class from the theme cookie; the marketing page hardcodes a light palette (`bg-[#f7faf9] text-slate-950`, teal/slate/amber literals) while the embedded shadcn `Dialog`/`Button`/`Input` use theme tokens — a dark-mode user gets a dark dialog and dark inputs inside a light page. Either force the light token scope on `.marketing-page` or restyle via tokens.

### P15C-P4 — `/` is fully dynamic on every anonymous hit

`app/page.tsx` calls `createClient()` (cookies) + the RPC per request, so the marketing page can never be static/ISR-cached. Consider fetching registration status with a cookie-less client + `revalidate`, or accepting the cost knowingly (document it).

### P15C-P5 — Progress meter lacks ARIA semantics

[components/marketing/marketing-page.tsx:64](../../components/marketing/marketing-page.tsx#L64): the spots-taken bar is presentational divs; add `role="progressbar"` + `aria-valuenow/min/max` or `aria-hidden` (the text above already conveys it — then mark the bar decorative).

### P15C-P6 — Dynamic `await import("next/navigation")` for `redirect`

[app/page.tsx:24](../../app/page.tsx#L24): no reason to lazy-import; import `redirect` statically at top like the previous implementation.

### P15C-P7 — `(public)` layout brand link still targets `/early-access`

[app/(public)/layout.tsx:4](<../../app/(public)/layout.tsx#L4>): signup/invited-signup pages' logo now costs an extra 308 hop; point it at `/`.

### P15C-P8 — Redirect test is a source-string grep

[tests/unit/pages/p15c-early-access-redirect.test.ts](../../tests/unit/pages/p15c-early-access-redirect.test.ts) asserts the literal `permanentRedirect("/#early-access")` appears in the file — brittle and behavior-free. Fold a real redirect assertion into the R3 e2e fix.

### P15C-P9 — Spec section/motion coverage is loose

No dedicated Screenshots section (the hero product mock arguably stands in); "informational content run in modal dialogs" is only realized for the early-access form (FAQ uses `details/summary` — arguably better); scroll-reveal exists only as a load-time hero animation, not on-scroll section reveals. Acceptable as design judgment, but the implementer should either close the gap or record the deviation.

### P15C-P10 — Plan revision still uncommitted (hygiene, carried)

The revised `docs/AI_AGENT_PLAN.md` — the authority for all P1.5 reviews — still lives only in `stash@{0}`. Commit it (first raised in P1.5B as part of P15B-R10's hygiene note).
