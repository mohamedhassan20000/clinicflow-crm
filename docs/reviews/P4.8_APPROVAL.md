## 2. Blocking verification gap

### P48-L4-R1 — live revenue-context coverage uses the removed schema

`tests/unit/integration/p4a-ai-tools-rls.test.ts:536` supplies:

```ts
{
  type: "revenue",
  dateRange: { from: "2026-07-01", to: "2026-07-31" },
  filters: { doctorId: doctorBId },
}
```

The final strict contract deliberately rejects `filters`. At line 543, `parseAssistantPageContext(pageContext)` therefore returns `null`. The test then proves only that a dropped/absent context produces a null patient binding; it does not prove that the valid final `{ type: "revenue", dateRange }` context remains non-patient.

The matrix also calls `ensureDoctorConversation` for a new id but never calls `persistDoctorTurn` or reselects an inserted row. By design, `ensureDoctorConversation` keeps the first turn virtual. The matrix therefore verifies conversation binding, not the documentation's stronger claim that every context produces a persisted general conversation with `patient_id = null`.

This conflicts with:

- `docs/reports/P4_8B_IMPLEMENTATION.md:91`, which says live persistence isolation proves every P4.8B non-patient context;
- the final comprehensive-fixes report's general claim that scenario/documentation gaps are closed; and
- the requested final-verification condition that tests and documentation accurately cover the final implementation.

### Required correction

1. Replace the stale live fixture with the valid date-only revenue context.
2. Assert that `parseAssistantPageContext(pageContext)` is non-null for every valid matrix row before deriving `patientId`; this prevents future strict-schema drift from becoming another false-positive.
3. Either persist and reselect the conversation when claiming live persistence coverage, or accurately scope the documentation to the null patient-binding behavior that the current test checks.
4. Rerun the focused P4.8 suite and the complete live integration/RLS suite.
5. Correct or explicitly date/scope any P4.8B validation/coverage statement that still describes the pre-fix test set as final.

No production implementation change is required by this finding.
